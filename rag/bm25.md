# BM25：基于关键词的相关性排序

## 一句话理解

BM25（Best Matching 25）是一种经典的文本检索排序算法：给定查询词，它为每个文本块计算相关性分数，再按分数从高到低返回。它关注的是词项是否匹配及其统计特征，不理解句子的语义，也不需要神经网络或 Embedding 模型。

在 RAG 中，BM25 通常作为稀疏检索的一路，适合补足向量检索对专有名词、型号、章节标题和原文术语的精确匹配能力。

## 它如何给文本打分

BM25 综合三类信息：

1. **词频（TF）**：查询词在文本块中出现得越多，通常越相关；但重复次数的收益会逐渐变小，不会无限线性增长。
2. **逆文档频率（IDF）**：越少见的词越有区分力。若某词几乎出现在所有文本块中，它对排序的帮助很小；稀有的人名、模型名或术语权重通常更高。
3. **文本长度归一化**：控制长文本仅因包含更多词而获得不公平优势。同一个查询词，在较短文本中出现，往往比在很长文本中出现更能说明相关性。

一种常见的 BM25 写法是：

```text
BM25(q, d) = Σ(t ∈ q) IDF(t) × [ f(t,d) × (k1 + 1) ]
                           / [ f(t,d) + k1 × (1 - b + b × |d| / avgdl) ]

IDF(t) = ln(1 + (N - df(t) + 0.5) / (df(t) + 0.5))
```

其中：

| 符号 | 含义 |
| --- | --- |
| `q` | 查询中的词项集合 |
| `d` | 一个待排序的文档或 RAG 文本块 |
| `f(t,d)` | 词项 `t` 在 `d` 中出现的次数 |
| `df(t)` | 包含词项 `t` 的文档/文本块数量 |
| `N` | 参与统计的文档/文本块总数 |
| `|d|` | `d` 经分词后的长度 |
| `avgdl` | 全部文档/文本块的平均分词长度 |
| `k1` | 控制词频收益饱和速度的参数 |
| `b` | 控制长度归一化强度的参数，通常在 `0` 到 `1` 之间 |

不同搜索引擎可能采用略有差异的 BM25 变体或统计范围，因此不同系统的 BM25 原始分数不一定能直接比较。上面的公式用于解释核心机制；具体实现应以所用检索引擎的文档为准。[BM25 原始框架综述](https://doi.org/10.1561/1500000019)

## 参数直觉

- **`k1`**：控制词频饱和。取值较低时，词项出现几次后加分就趋于饱和；取值较高时，重复出现还能继续增加分数。
- **`b`**：控制长度归一化。`b=0` 表示不做长度归一化；`b` 越大，长文本受到的长度校正越强。
- **`avgdl`**：语料或字段的平均分词长度。查询标题、标签等短字段时，平均长度应和该字段相符，不能机械套用正文长度。

Qdrant 文档给出的 `qdrant/bm25` 常见默认值是 `k=1.2`、`b=0.75`、`avg_len=256`。这里实现里的 `k` 对应常见公式记号中的 `k1`。这是默认参数，不代表所有语料都最优；调整后应使用真实查询集验证排序效果。[Qdrant BM25 文档](https://qdrant.tech/documentation/search/text-search/full-text-search/)

## 一个直观例子

查询：`Qdrant BM25 中文分词`

- 文本块 A 包含“Qdrant BM25 使用 multilingual tokenizer”，虽然很短，但命中了较具体的术语。
- 文本块 B 是一段很长的通用介绍，只偶然出现一次“BM25”。
- 文本块 C 没有这些原词，但用另一种说法解释了相似概念。

BM25 通常更容易把 A 排在前面：它命中了多个查询词，且这些术语在语料中有区分度；B 会受到词频饱和和长度归一化影响；C 若词项不同，BM25 未必能判断它“意思相近”。这正是 BM25 与语义向量检索互补的原因。

## BM25 的优势与边界

**适合：**

- 查询包含精确术语、名称、编号、型号、缩写或标题；
- 需要结果可解释：可以检查哪些查询词命中了文本；
- 没有 Embedding 服务，或希望增加一条不依赖 Embedding 模型的召回通道。

**局限：**

- 它按词项匹配，不天然理解同义词、改写、上下位关系或跨语言语义；
- 分词和文本规范化会直接影响结果。中文、英文混合文本、代码标识符、连字符和专有名词需要特别测试；
- 文本块过大容易稀释主题，过小则可能缺少足够上下文，因此 BM25 的效果也受切块策略影响。

BM25 里的“词项匹配”不一定是原始字符串逐字相等。引擎会先进行分词、大小写或词干等处理；入库与查询必须使用一致的处理配置。Qdrant 也特别提示，面向非英语语料时应检查 tokenizer、词干和停用词配置。[Qdrant 文本处理说明](https://qdrant.tech/documentation/search/text-search/full-text-search/)

## 在混合 RAG 中的位置

一条典型的混合检索流程是：

```text
文本块 ──┬── Embedding 向量 ── Dense 语义检索 ──┐
        └── BM25 稀疏表示 ── 关键词检索 ──────┴── RRF 融合 ── Reranker 精排
```

- **Dense 检索**擅长查询改写和语义相近内容，即使查询词与原文用词不完全相同，也可能召回。
- **BM25 检索**擅长原文词项命中，尤其是稀有实体和精确术语。
- **RRF（Reciprocal Rank Fusion）**负责合并两路排序结果；它是融合算法，不是 BM25 的一部分。
- **Reranker**可以对初步候选重新排序；它不能找回两路召回都没有提供的文本块。

在 Qdrant 中，BM25 可由 `qdrant/bm25` 将文本表示为稀疏向量，查询时也使用相同模型和文本处理选项；集合配置 IDF modifier 后，Qdrant 会用语料统计参与排序。这里的“稀疏向量”不是 Dense Embedding 那种由神经网络生成、表达语义相似度的向量：它主要记录文本中出现了哪些词项及其权重，因此不需要调用 Embedding 模型服务。两者是不同的表示与召回通道。[Qdrant 全文检索与 BM25](https://qdrant.tech/documentation/search/text-search/full-text-search/)、[Qdrant FastEmbed BM25 实现](https://github.com/qdrant/fastembed/blob/main/fastembed/sparse/bm25.py)

## 调试与验收建议

1. 用包含专有名词、普通问题、同义改写、错别字和中英混合术语的固定查询集测试。
2. 检查 tokenization 结果；若查询词和文档词被切成不同 token，BM25 就无法按预期匹配。
3. 单独观察 BM25 召回，再观察 Dense、融合和 Reranker 的结果，避免把某一阶段的问题误判成另一阶段的问题。
4. 除了看最终答案，还应检查 Recall@K、MRR 或 NDCG 等检索指标及引用页是否准确。
5. 调整 `k1`、`b`、`avg_len` 或切块策略后，用同一查询集回归；不要只凭少数手工问题判断效果。
