# RRF：把多路检索结果合成一份排序

## 一句话理解

RRF（Reciprocal Rank Fusion，倒数排名融合）用来合并多个检索器各自排好的结果。它不比较 BM25 分数和向量相似度分数，而是看同一个文本片段在每份结果里排第几：排得越靠前，贡献越大；在多份结果里都靠前，最终通常也会靠前。

可以把它理解成“多个评委分别给候选项排名，再按名次投票”。Dense 检索和 BM25 不必使用同一套分数，RRF 只需要它们都返回可识别的文档/文本块及其排名。

## 为什么需要 RRF

在 RAG 中，Dense 和 BM25 各有擅长之处：Dense 更容易找到换了说法但意思相近的内容，BM25 更容易找到原文里的专有名词、型号和编号。但两者的原始分数不是同一种单位：向量相似度可能在一个范围内，BM25 分数则可能是另一种尺度，直接相加没有可靠含义。

RRF 绕过分数尺度问题，只用排名融合结果。它不负责查文档，也不生成回答；它接收已经完成的多路检索结果，再排出一份合并后的候选列表。

## 它怎么算

一个常见写法是：

```text
RRF(d) = Σᵢ 1 / (k + rankᵢ(d))
```

其中：

| 符号 | 含义 |
| --- | --- |
| `d` | 某个文档或文本块 |
| `i` | 一路检索结果，例如 Dense 或 BM25 |
| `rankᵢ(d)` | `d` 在第 `i` 路结果中的名次，下面的手算例子从 1 开始 |
| `k` | 平滑常数，控制前后名次的分值差距 |

如果一个文本块没有出现在某一路的候选列表里，该路就不给它加分；把它在出现的各路得分相加，再按总分从高到低排序。**排名越靠前，单路贡献越大；被多路共同排在前面的片段通常会得到更高的总分。**

`k` 越大，不同名次之间的贡献差距越小，靠后的结果不会那么快被压低。它改变的是融合时对各名次的折扣，不会改变 Dense 或 BM25 自己的原始排序。

## 手算一个例子

假设同一个问题得到两份候选排序：

| 名次 | Dense 语义检索 | BM25 关键词检索 |
| --- | --- | --- |
| 1 | A | B |
| 2 | B | C |
| 3 | C | D |

为了方便手算，暂用 `k=1`：

- A：只在 Dense 排第 1，得分 `1/(1+1) = 0.50`。
- B：Dense 排第 2、BM25 排第 1，得分 `1/(1+2) + 1/(1+1) ≈ 0.83`。
- C：Dense 排第 3、BM25 排第 2，得分 `1/(1+3) + 1/(1+2) ≈ 0.58`。
- D：只在 BM25 排第 3，得分 `1/(1+3) = 0.25`。

合并后是 `B > C > A > D`。B 虽然没有任何一路单独排第一，但两路都把它排得很靠前，因此融合后排第一。这展示了 RRF 的核心：利用多路排序的共同支持，而不是偏信某一路的原始分数。

例子里的 `k=1` 只是为了便于理解，不是推荐配置。经典论文的排名从 1 开始，使用过 `k=60`；Qdrant 当前文档的默认公式使用从 0 开始的名次，并给出 `k=2` 的默认值。不同实现的名次起点、公式和默认值可能不同，不能只照抄一个 `k` 数字；使用时以所部署版本的文档为准。[Qdrant RRF 公式与参数](https://qdrant.tech/documentation/search/hybrid-queries/)、[原始 RRF 论文](https://doi.org/10.1145/1571941.1572114)

## 在混合 RAG 中的位置

```text
用户问题
   ├── Dense 检索 → 排序列表 ──┐
   └── BM25 检索  → 排序列表 ──┴── RRF 合并 → 候选结果 → 可选 Reranker 精排
```

RRF 和 Reranker 不是一回事：

- **RRF**只根据各检索器给出的名次计算融合分，不再读取文本的语义，也不需要另一个模型。
- **Reranker**会把问题和候选文本再交给相关性模型逐条评分，用来精排较小的候选集合。

常见顺序是先并行召回，再用 RRF 合并；如果需要更精细的排序，再让 Reranker 对融合后的少量候选重排。Qdrant 的混合查询也采用“多路预取，再做 RRF 融合”的结构。[Qdrant 混合查询](https://qdrant.tech/documentation/search/hybrid-queries/)

## RRF 的优势与边界

**优势：**

- 不要求不同检索器的原始分数可比，也不必先把它们归一化到同一尺度；
- 算法简单，不需要训练一个融合模型；
- 能让在多路检索里都表现靠前的片段获得共同支持。

**边界：**

- 它只会重排输入结果里的候选。某段文本如果没有进入任何一路的候选列表，RRF 无法把它“找回来”；
- 它看名次、不看原始分数差距。某一路第 1 名只比第 2 名略好，和远远领先，在基础 RRF 里都会只体现为相差一个名次；
- 默认通常把各路结果同等对待。若要加权，应先用代表性查询和相关性标注验证，避免某一路整体变差却仍影响最终排序；
- 融合分只是排序用的分数，不是答案正确概率，也不表示模型有多确信。

## 工程实践与排查

1. **确保各路结果能识别为同一片段**：用稳定的文本块 ID 合并；不要只凭内容字符串猜测重复项。
2. **检查每路的候选深度**：RRF 只能合并已召回的结果。候选取太少，会让相关片段在融合之前就被截掉；增大候选数则会增加后续处理成本。
3. **先分别检查，再检查融合**：记录 Dense 排名、BM25 排名、融合分和最终名次。若正确片段两路都没召回，问题不在 RRF。
4. **不要把分数直接相加代替 RRF**：不同检索器原始分数范围不同，直接相加可能让数值范围较大的那一路支配结果。
5. **用固定问题集比较**：分别评估 Dense、BM25 与融合后的 Recall@K、MRR 或 NDCG，并确认引用文本和页码正确。
6. **谨慎调 `k` 或权重**：参数可能影响各名次贡献的差异；要用训练/验证问题集调参，再用未参与调参的问题检查效果。
